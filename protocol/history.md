# History

The compartment of the past. It exists so that the same thing is never discussed twice.

**Nothing here is needed to apply the protocol.** [`protocol.md`](protocol.md) carries the current state and is self-sufficient; what has been learned is already in what it says. This file points to it; it never points here.

A decision is never erased: it moves to `lapsed`, with its reason. Statuses: `solid` · `provisional` · `to-decide` · `lapsed`.

**Section numbers.** Until PR-89 the text had fourteen sections; an entry written before it names them as *former section N*, the text as it stood then. [`specs/reduction/mapping.md`](specs/reduction/mapping.md) maps each former rule to its place in the current six sections, or records that it left.

---

## Where the current state comes from

The protocol was forged on a first instance — `ColibriCommon` (Viseo), the "cartridges" workstream of the SQL migration engine — in four contradictory **revisions** — between a human arbiter, a session playing red against the text, and a session holding the repository — without a single round of the protocol being run. Original measurement on that instance, and the protocol's reason for being: **60% line coverage for a 24.3% mutation score** — more than one deliberate change to the code in two went unnoticed.

The protocol was then extracted from that instance and made agnostic. Its current form — a current state with neither past nor future in the text, sharpened by execution rather than revised — is the result of the overhaul recorded in PR-44, PR-45 and PR-46.

The protocol was written in French, in [`protocole-agents-adversariaux`](https://github.com/Bilou0412/protocole-agents-adversariaux). On 1 October 2026 it was translated in full into English, and the arbiter decided that **this English distribution is the only canonical one**: the French repository is frozen at its last state and is no longer kept in sync. Two normative texts for one protocol would be the drift that former section 5 forbids. The protocol is sharpened here, and only here.

## Founding decisions — `PR-xx`

| **PR-74** | **Two layers, one paradigm, each with its oracle.** The theoretical layer produces the spec: a **searcher** pools everything at its source and chooses nothing; a **blue** constructs; the **yellow** attacks the proposal then the spec; a **cold judge** settles claim by claim what stays contested. The technical layer produces the code: red against green, the **erudite** reduced to the technical gaps that must be constrained. ## What training has produced

A run round that triggers a sharpening ([`protocol.md`](protocol.md) former section 11) leaves its trace here: the finding, the audit, the in-place modification. The strict text keeps none of it — only the rule as it is written now.

**An arbitration is not a sharpening.** The decisions above are the arbiter's arbitrations on the text: they clarify what the protocol already is. A sharpening, by contrast, starts from a finding produced by a run round — and so cannot come from a rereading. This table fills only by producing.

**Borderline case — PR-52.** The finding that produced it does not come from a rereading: a real run on this repository exhausted the session's quota before completing, work lost. It was not a protocol round — neither spec, nor red, nor green — so it is not a sharpening and the table below stays empty. But it is the first finding this repository owes to execution rather than reasoning, and it shows that the boundary between arbitration and sharpening turns on *what produced the finding*, not on who records it.
